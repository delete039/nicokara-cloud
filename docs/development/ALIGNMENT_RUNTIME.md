# 双模型对齐运行约束

Yohane 与 MMS-FA 都运行在可终止子进程中，共享配置的并发信号量。模型使用原始混音；RMS 活动检测不能区分伴奏与人声，因此不能据此把一个音拍扩展到整个音乐片段末尾。

完整视频和音频上传使用同一模型入口，包含注音确认后的恢复分支。引擎支持对齐模式时必须显式传递所有模式，包括 `standard`；遗漏它会触发引擎默认的 `auto`，选择 Yohane 而非 MMS。

## 声学推理

`backend/app/alignment/ctc.py` 每次推理 1000 帧核心，前后各保留 100 帧上下文。对于 16 kHz wav2vec2，这对应 20 秒核心和每侧 2 秒上下文。仅保留核心输出并移到 CPU，随后对整首歌统一进行 CTC 对齐。

输入窗口必须从 320 样本网格开始；特征提取器的感受野是 400 样本。总帧数为 `floor((samples - 400) / 320) + 1`。直接拼接任意 20 秒音频的输出会丢失边缘帧，造成随歌曲长度累积的时间偏移。

## CTC 与边界

普通字符级 CTC 允许同一音拍的辅音出现在间奏前、元音出现在间奏后。音拍内空白使用每帧 0.1 的对数概率惩罚；完整音拍之间的空白不加惩罚。该约束参与路径搜索，不裁剪最终时间戳，也不提高 8 秒 / 15 秒的异常音拍拒绝阈值。输出置信度仍来自原始声学概率。回溯矩阵最多 1 亿字节，超出时返回明确错误并走已有降级流程。

MMS 的 RMS 边界修正最多移动 250 ms，只接受相邻且覆盖当前末尾的活动区间。压缩音频的片段连接处，开始时间映射到后一片段，结束时间映射到前一片段，避免把被移除的静音算入末音。

模型时间轴只填平不超过 250 ms 的高亮间隙，保留较长停顿，避免已经通过验证的音拍在后处理阶段再次被拉长。

Yohane 保留模型配置中的 CTC blank ID，单次混合声道；音频速度不为 1 时先实际变速，再按同一倍率还原时间轴。

## 诊断与验收

管理员日志 `external.alignment_attempt_failed` 记录每个失败模型及原始错误；`external.alignment_completed` 记录真正成功的引擎、模型、耗时与置信度。异常音拍错误包含模型、索引、起止、得分与阈值，避免后一个模型的错误遮蔽前一个。

验证应分别执行 Yohane 与 MMS，检查最终 `alignment_engine`，不能把 Whisper 降级成功当作模型验收。使用隔离副本与有内存上限的诊断进程，不在生产服务中重放无界推理。单元测试覆盖窗口接缝、长间奏、重复字符、长元音、音频结束边界和质量拒绝；部署后仍需完整歌曲验证。
